F1
🔴 Critical FAB bell unlabeled — no affordance for "notify employees"
Lily Brooks Leo Thomas Priya Patel · fabOverlay, bottom-right

All 3 personas failed to immediately recognise the FAB as the bulk notify entry point. The bell icon in iOS convention means "my notifications" — Leo explicitly hesitated; Priya skipped it entirely until step 8. The FAB is the sole path to bulk notify in v8 + FAB mode, yet carries no text label or contextual tooltip.

✦ Proposed solution S2 — Dim warning rows + inline explanation on swipe attempt [S]

Render warning-level rows at reduced opacity (0.55) with a small ⓘ icon trailing the pill. On swipe attempt, show a brief inline toast: "Notifications are sent for missed clock-ins only." This preserves the policy while eliminating the silent dead end.

F3
🟡 Major FAB tap silently resets active filters
Lily Brooks Leo Thomas · enterFabSelection(), filter state

enterFabSelection() replaces selectedFilters with actionableFilterCategories — the list visibly re-renders with different employees. A user who had filtered to "Missed clock-ins" will see their filter silently replaced by 4 categories. The previous filters are saved and restored on cancel, but users aren't told this. Lily noticed the list changed and paused; Leo didn't notice and got lucky.

▸ Code evidence 
private func enterFabSelection() {
    filtersBeforeFab = selectedFilters           // saved but not communicated
    selectedFilters = Self.actionableFilterCategories  // silent override
    isSelecting = true
    selectedForNotification = selectableEmployeeIDs
}
✦ Proposed solution S3 — Show a brief "auto-filter" banner when entering selection [S]

When entering FAB selection mode, display a non-blocking 3-second banner at the top of the list: "Showing employees you can notify" with a small "Restore filters" link. Alternatively, keep the user's existing filters and grey-out non-notifiable rows in place so they retain context without a jarring list change.

F5
🟡 Major Swipe-to-notify has zero discoverability
Priya Patel · Employee row trailing swipe actions

Swipe-to-notify is the right path for single-employee notifications, but has no visual hint — no trailing chevron, no peek indicator, no onboarding gesture. Priya found it only by guessing. Lily and Leo never tried it. For HR admins who need to notify one person selectively (not the whole bulk), the feature is functionally invisible.

▸ Code evidence 
// swipeActions applied with no visual affordance on the row itself

        Button { ... } label: {

        }

    }
}
// No trailing icon, no peek animation, no onboarding hint
✦ Proposed solution S5 — Swipe-hint animation on first load [M]

On first appearance of the Attendance tab in a session, animate a brief "peek" on the topmost actionable row — slide ~24pt left to expose the Notify action, then spring back. This is the standard iOS Mail/Reminders gesture-teaching pattern. Additionally, consider a small trailing bell icon on each actionable row (when not in FAB selection mode) so the action is scannable without gesturing.

F6
🟢 Minor Stats pills visual weight implies CTA but they're filter controls only
Leo Thomas · v6StatsRow, Attendance tab header

The three summary pills carry bold danger-red counts in colored capsules with card shadows — visual weight that signals "primary action" to low-frequency users. Leo tapped one expecting a notify action or drill-in. They only filter the list below. The pills are useful as filters, but mislead users who haven't internalised the filter pattern.

✦ Proposed solution S6 — Add "Filter by" label above the stats row [S]

Add a 12pt secondary-color label "Filter by" above the horizontal scroll row, left-aligned. This single label disambiguates the pills' purpose without changing their design. Secondary option: reduce the pill card shadow (radius 3 instead of 7) to lower their perceived interactivity level.

Verdict

The core notify flow works, but discovery is nearly accidental in v8 + FAB mode. All three personas struggled to locate the FAB — the only entry point to bulk notifications — and none received any confirmation that the action succeeded. F1 (unlabeled FAB) and F4 (silent completion) are the two highest-priority fixes — both affect every persona, both require only small engineering effort, and together they transform the flow from guesswork into a confident action.
